# MuxMender 20260929-v42

## Sharing the GPU

Resource settings now include **Yield GPU to other apps**, off by default.
With the restricted host monitor configured, competing work blocks new starts.
Sustained activity pauses supported media stages; 60 seconds of quiet permits
resumption. Paused stages keep their GPU memory. Missing or stale telemetry
blocks new starts but releases active workers rather than stranding them.

The dashboard shows the reason for yielding. Stage timeouts exclude suspension,
and cancellation still works. Linux workers have parent-death cleanup so a
suspended worker does not survive its supervisor. Restarting still requires
normal interrupted-job recovery; this is not a durable encode checkpoint.

This is an opt-in first release, not a hard GPU quota or a guarantee of playback
latency. Only shared native-stage workers participate; other subprocess readers
may continue. Cross-container production qualification remains a deployment
check. Do not claim every HDR filter path has been qualified by short SDR tests.

## Other pending reliability fixes included

- Validation-slot waiting does not consume the subsequent processing timeout.
- Bound shared HDR preflight evidence avoids making a contradictory decision
  from a separate single-scene size estimate. Full-file savings and preservation
  still have to pass.
- A Matroska mux path avoids unlimited buffering around sparse subtitle streams;
  memory guards and seek/timing/metadata checks remain. The full research case
  ultimately missed the savings target and retained its original; it is not a
  newly approved replacement.
- Clearer mux failure details and native mux progress reporting.
- Narrow deduplication of repeat structural AV1 trial failures; this is not a
  repair for source frame/timestamp defects.

Quality thresholds, source resolution and publication safeguards are unchanged.
The larger workspace redesign/mockup and bulk queue-clear control are not part
of this build. Outstanding AV1 timing and damaged-audio cases remain unresolved.

## Evidence

Generated RTX 5050 H.264, HEVC and AV1 encodes produced identical decoded frames
and timing with and without a temporary pause (96 frames per comparison).
A generated paused mux preserved all 171 packet payloads and timestamps.
Targeted Linux regression and parent-death tests passed; detailed scope is in
`docs/cooperative-pause.md`. No source media was changed by qualification.

## Deployment

Keep the queue paused while updating the existing app to
`muxmender-app:20260929-v42`. Retain current GPU assignment, media/output mounts,
UID/GID and port mappings. The release archive is a **Docker build context**, not
a prebuilt image; the stage script builds and import-checks it without deploying.

For GPU sharing, add a **read-only directory mount**:

- Host: `/run/muxmender-gpu-monitor`
- Container: `/gpu-telemetry`

Set `MUXMENDER_GPU_TELEMETRY=/gpu-telemetry/activity.json`. The host monitor must
start at boot before this mount is used. Mount the directory, not the JSON file,
because telemetry updates replace the file atomically. Confirm v42 and fresh
telemetry before enabling the setting. Queue resume remains a separate action.
