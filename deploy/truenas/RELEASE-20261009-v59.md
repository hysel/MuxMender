# MuxMender 20261009-v59

## Fixes for MP4 chapters and audio timing

Native QuickTime chapter-text tracks are handled without the incompatible MOV
copy path. The shared engine checks every chapter packet against its title and
start/end time before translating the duplicate native representation. It
preserves language, handler, disposition and ordinary chapter metadata, and
repeats those checks on the output. Only two verified default chapter descriptors
can be regenerated; custom descriptors and unknown data are not discarded.

Audio, frame and packet readers avoid a redundant QuickTime chapter parse when
no unclassified data tracks remain. Normal metadata probing and final chapter
comparison still read chapters. Other decoder errors remain strict failures.

AAC priming is checked against the audio track's recorded presentation start,
not an assumed zero timestamp. The tolerance is still one audio sample. Source
reader errors are no longer all described as audio corruption in the results UI.

## Queue file sizes

Current work shows the combined size of running and waiting source files, plus
separate running/waiting totals and sizes beside individual waiting videos.
Finished history is excluded. Unknown sizes and stale responses are labelled;
these totals are not temporary disk use or predicted savings.

## Tests and limits

All eight affected sources passed targeted qualification: six complete
chapter-preserving stream-copy remuxes and eight strict five-second audio reads.
All source stats were unchanged and temporary remux videos were removed.
Another 51 Linux regression tests passed, including corrupt-audio rejection.
Queue-size and workspace UI regressions also passed locally.

These checks are not full-conversion or visual-quality approval. Retried jobs
must still pass the usual full quality, timing, audio, metadata, savings and
publication checks. The two independent decoder-error cases remain failures.
No quality thresholds were lowered and no source files were replaced by these
tests. All v58 features are retained.

## Build and install

Run the staged script as admin with the archive SHA256 supplied alongside the
package. It builds and smoke-tests a separate `muxmender-app:20261009-v59` image,
including generated NVIDIA HEVC/AV1 frames. It does not change the installed app
or queue. Wait for `status=passed` in the stage's `result.txt`, then change the
TrueNAS app image tag to `20261009-v59`, retaining its existing mounts/settings.
