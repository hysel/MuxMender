# MuxMender 20261003-v54

## Fix for audio checks that restart their sample clock

A diagnostic audio filter can restart its counter when a decoder reinitializes.
That made a valid source fail the discard-only audio check. For this specific
timestamp error, the app now repeats the complete strict decode using the
original timestamps. Decoder errors still fail. This does not change the audio
in the delivered file or remove packet, timeline, metadata or quality checks.

The actual failing source passed the new full-file check on TrueNAS across all
three audio tracks. Its complete hash was unchanged. This is source-check
qualification, not proof that a full replacement has passed in production.

## Faster HDR quality scoring

PQ quality scoring can use four workers when measured CPU, task and memory
headroom permit it, including at least eight GiB available. Otherwise it uses
two. Shared validation admission can reduce the allocation further under load.
The decoder settings, HDR rendering, frame alignment and quality thresholds
are unchanged. Untested profiles keep the existing two-worker path.

Six balanced comparisons per generated test produced identical per-frame
scores. Median scoring time fell from 42.25 to 29.77 seconds for a 30-second
1080p test, and from 27.30 to 17.27 seconds for a five-second 4K test. These
are about 30% and 37% less scoring time, not whole-conversion speed promises.
Peak memory for the 4K test increased by about 0.4 GiB.

All v53 queue responsiveness, GPU admission and qualified GPU-reader changes
remain included. Existing quality and safe-replacement checks remain required.
