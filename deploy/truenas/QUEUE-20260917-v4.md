# Opt-in autonomous season queue (v4)

This release is prepared, not deployed automatically. Wait until existing
manual jobs finish before updating the app. Never run manual batches alongside
the queue. The queue waits for tracked active jobs but cannot reserve resources
against a manually launched process racing with it.

## Deployment

```sh
sudo docker build -f /mnt/FR4G/Apps/muxmender/app-build-20260917-v4/deploy/truenas/Dockerfile.app \
  -t muxmender-app:20260917-v4 /mnt/FR4G/Apps/muxmender/app-build-20260917-v4
```

Edit the existing TrueNAS app:

- Image repository `muxmender-app`, tag `20260917-v4`, pull policy Never.
- Keep UID/GID 3005, GPU assignment, port, allowed hosts and password unchanged.
- Keep `/media` read-only and `/output` writable, on separate mounts.
- Clear/remove `MUXMENDER_SOURCE` so no one-shot job is submitted.
- Set `MUXMENDER_QUEUE_ENABLED=true` (default is false).
- Keep `MUXMENDER_PLAYBACK_CODECS=hevc,av1` for our tested players.

Save once. The queue starts inside the app, and new jobs appear automatically.
The dashboard's App configuration section shows queue state, scan progress,
per-file outcomes, and the approved scope. Existing job cards show detailed
encoding/validation progress. Refresh the browser once after upgrading its UI.

## Fixed authorization boundary

Only `/media/TV/Series A/Season 1` and its subdirectories are eligible.
The scope is deliberately not a general user-supplied path in this first release.
Symlinks escaping this scope are excluded. No source file is ever written,
renamed, replaced, or deleted by this queue. Outputs are retained under
`/output/autonomy/item-*`, and passing copies require playback review and a
separate explicit replacement approval. There is no automatic media cleanup.

The existing GPU runtime tests and codec selection are reused. CPU fallback is
not enabled. The strict SDR eligibility policy remains; unsupported input is
reported rather than converted. Mean VMAF 95, fifth percentile 90, and minimum
10% savings remain unchanged. Frame geometry/timing, color, copied tracks,
decoding and source hashes remain checked. Three-scene scores are screening,
not a mathematical guarantee of whole-video perceptual transparency.

## Persistence, pause and recovery

- Queue state is atomically saved in `/output/autonomy/queue.json`.
- One queue owns the output lock, and it runs one worker at a time.
- Initial scanning hashes files and imports terminal existing comparisons by
  content hash. Previously evaluated content and deployed encoded copies are
  skipped. Later unchanged files are recognized by size and nanosecond mtime.
  Same-size changes with deliberately preserved timestamps are not detected.
- New/changed files are discovered on a 30-second idle cycle. Hashing a large
  library may take time but does not modify it.
- Interrupted work is marked for review and is not automatically retried.
- Two consecutive worker failures pause new submissions. Failed inputs are not
  retried unless changed. A clean skip is not a worker failure.
- Less than 12 GiB free pauses starts; before a particular file starts, space
  must also be at least three times its size. Workers enforce a 12 GiB floor.
- Disabling the queue and restarting the app stops owned processing; partial
  outputs are retained. Read-only mount checks are enforced again before work.

Pause after the current job (administrator shell):

```sh
sudo docker exec --user 3005:3005 ix-muxmender-muxmender-1 \
  python3 -c "from pathlib import Path; Path('/output/autonomy/PAUSE').touch()"
```

After reviewing the problem, allow remaining work to continue:

```sh
sudo docker exec --user 3005:3005 ix-muxmender-muxmender-1 \
  python3 -c "from pathlib import Path; Path('/output/autonomy/PAUSE').unlink(missing_ok=True)"
```

This removes only the pause marker, not media. If the queue reports
`paused-error`, fix the cause and restart the app too. Interrupted/failed files
remain held for manual review; removing the pause marker does not retry them.
Dashboard HTTP endpoints remain read-only, with existing host/password guards.
