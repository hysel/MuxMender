# MuxMender 20260923-v39

This update lets more sources reach a measured conversion trial while keeping
quality, timing, track preservation and verified replacement checks in place.

- Size-aware savings target: the smaller of 25% or 1 GB, with a 100 MB minimum.
  Fixed percentages remain available. Existing requests retain their settings.
- Shared NVIDIA Dolby Vision preservation paths for supported Profile 5, 7
  (MEL/FEL) and 8.1 sources. Fresh qualified results can use the normal replacement
  flow. Experimental results and old research copies are not promoted.
- Bundled, pinned FEL reconstruction runtime. It requires Linux x86-64,
  Python 3.12 and AVX2; unsupported bitstreams still need a working renderer.
- Source-driven handling of short videos, additional tracks, artwork, rotation,
  native MP4/MOV preservation and supported interlaced encoding attempts.
- Updated evaluation policy lets a new folder request reconsider outdated skips.
  Re-adding a folder does not automatically publish historical research output.

Evidence before packaging: 848 Linux regression tests passed; isolated non-root
image tests passed for FEL, MEL and Profile 5. Generated Profile 5/MEL replacement
transactions passed with reference fixtures unchanged. These are not a promise
that every source or GPU will pass. No library originals were used for publication
tests. The AVI-only MPEG-4 clock recovery extension remains future work.

## Deploy

Pause the queue and allow active work to finish before changing the image.
Build `muxmender-app:20260923-v39` from this context, then select that tag in the
existing TrueNAS app. Keep its storage, user, GPU and port settings unchanged.
If NVIDIA_DRIVER_CAPABILITIES is explicitly set, include
`compute,video,utility,graphics`. The portal uses the published port, currently
`http://192.168.1.232:8767/`, not the container's port 8765.

After deployment, confirm the version before adding the Animation folder again.
Select recursive scanning and your intended copy/replacement and savings options.
Deployment does not enqueue work or replace media by itself. Public redistribution
of the bundled runtime needs the dependency source/notice delivery review.
