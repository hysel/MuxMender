# MuxMender 20261009-v57

## Queue status stays usable during delayed resource updates

The dashboard now reads queue state, counts and request settings directly from
the running worker. Slow storage, history or resource checks no longer leave
those fields frozen in an old snapshot. Queue controls use the fresh response;
delayed resource readings remain clearly labelled as delayed.

This does not hide a lost connection or claim that old telemetry is current.
Unreachable queue responses still disable unsafe actions.

## Checks and scheduling remain unchanged

All v56 codec, quality, metadata, savings and replacement checks remain in place.
The app still dynamically admits up to four workers when its selected resource
profile and sustained headroom allow it. This release does not force four jobs,
lower quality thresholds or automatically add the experimental CQ22 setting.

An image-isolated SDR excerpt comparison completed four equal tasks in about
575, 601 and 383 seconds with one, two and four workers. All twelve tasks passed
their technical checks and 94/90 quality thresholds. Available memory changed
substantially between phases, so this is not a guaranteed whole-library speedup.

CQ22 passed one difficult scene but failed the subsequent five-scene 90/90
qualification and aggregate savings requirement. No full conversion was started;
the source remained unchanged and temporary media was cleaned.

## Qualification and administration tools

Research tools isolate imports to the image-owned engine and record its version,
module path and checksum. The approved-copy publisher uses the shared verified
replacement transaction, records durable lifetime-savings receipts and cleans
redundant work media. It requires explicit administrator invocation and exact
request identifiers; it does not rewrite a running queue's history.

The build launcher runs independently of the SSH shell and tests the packaged
runtime, regressions, dashboard/API, process reaping, NVIDIA encoder visibility,
qualified GPU reader and generated bitrate presets. Tests use private fixtures,
not production mounts. Deploy only after the new image's smoke checks pass.

Historical result cards for manually approved safe-copy replacements can still
show the old safe-copy state; their confirmed receipts are included in lifetime
space savings and retained for recovery. This release does not claim those cards
are reconciled automatically.
