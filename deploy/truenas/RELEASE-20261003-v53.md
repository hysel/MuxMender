# MuxMender 20261003-v53

## Responsive queue status

The controls API returns its last snapshot promptly while one background reader
refreshes history. Slow log and receipt reads no longer hold the queue mutex,
so they do not block queue actions. Delayed or failed refreshes preserve the
last snapshot time and show a clear status warning. Queue controls wait for
current status rather than acting on stale information.

## Complete GPU admission measurements

GPU stages now prime the host and container CPU counters before taking their
first admission measurement. Previously a fresh sampler lacked the CPU interval
and reported unavailable telemetry even when GPU readings were present.
Missing telemetry still keeps stages serial. Sustained headroom and measured
throughput gains are still required before admitting parallel GPU work.

The read-only TrueNAS check reproduced the missing first CPU value and found
all required fields after priming. All 67 Linux reader/admission regressions
passed. Local control, polling, resource and UI tests passed with platform skips.

All v52 GPU-reader improvements and existing quality, metadata, corruption,
cleanup and verified-replacement checks are included.

## Deploy

Image: `muxmender-app:20261003-v53`.
Pause the queue and wait for active jobs to finish before changing the app image.
Run the staged build and smoke-test script, then update the image tag after it
passes. Keep existing mounts, GPU assignment, ports and settings. Refresh the
dashboard and resume the queue when ready.
