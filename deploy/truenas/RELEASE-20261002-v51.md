# MuxMender 20261002-v51

## Starting again after cancellation

Adding a new processing request starts a queue stopped by cancellation.
Cancelled jobs stay cancelled. Explicit manual pauses and recovery pauses still
require Resume. Keep-only and history-skipped requests do not restart the queue.
Resource limits and GPU sharing can still delay when the new request begins.

## Validation scheduling

- Shared OS leases coordinate primary validation workers across processes.
  One stage may use up to four; two stages may share up to eight only after
  sustained headroom allows them. This is not a hard CPU or RAM limit.
- Final validation can pass fresh trial checks. Thirty-second aging restores
  FIFO priority, so other work cannot be starved indefinitely.
- Short GPU trials briefly yield to a queued CPU-validation backlog. The wait
  is bounded to thirty seconds; final validation is exempt. External GPU-sharing
  requests still take precedence.
- Cancellation, worker death and older-worker compatibility retain safe lock
  release. No timing, metadata, quality or savings requirement was removed.

## What the measurements mean

In a contended generated CPU queue, final validation completed 61.7% sooner;
the full batch took essentially the same time. All eighteen complete frame
reports matched. Eighty Linux regressions passed before that experiment.
This is a final-result latency improvement, not a whole-conversion speedup or
GPU/HDR performance certification. The slower fixed-four-worker proposal was
rejected. Production NVIDIA presets remain unchanged.

All v50 UI, API, evidence reuse, adaptive resource and cleanup fixes are included.

## Deploy

Image: `muxmender-app:20261002-v51`.
Pause/drain or cancel and wait for active work to stop before updating.
The stage script builds and tests an isolated image without switching the app
or changing source files. After checks pass, update only the image tag and retain
existing mounts, GPU assignment, port, UID/GID and monitor configuration.
Refresh the browser, inspect the saved queue, and resume intentionally paused
work if needed. Existing history remains; cancelled jobs are not resurrected.
