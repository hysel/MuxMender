# v62 — FFmpeg 9 native runtime and resource controls

Candidate package; not published or deployed. The stable channel does not change
until this exact image passes qualification and its release materials are reviewed.

## Included

- FFmpeg 9.0.2 command-line tools and GPU reader, plus PyAV 19 using FFmpeg 9
  libraries. No FFmpeg 8 fallback is intended in this image.
- CPU allocation based on available CPUs, container quotas and user ceilings.
  Cooperative yielding responds to competing CPU/GPU activity; pausing does not
  release GPU memory. Shared quality and preservation checks remain unchanged.
- Scoring thread budgets, qualified GPU-reader dispatch and optional CUDA input
  research support. Not every format or GPU receives the same acceleration.
- Recovery and UI updates, including eligible-copy filtering and clearer resource
  controls. Container recreation does not promise exact-frame encode continuation.
- Updated stable-channel installation instructions for TrueNAS and standalone
  Docker, including Windows Docker Desktop WSL 2 guidance. Windows end-to-end
  conversion and replacement have not been qualified.

## Evidence and remaining checks

The preceding integration image passed 268 runtime checks, 110 integration checks,
ten generated GPU checks and safe-copy/cancellation recreation checks. Overlapping
Node-dependent skips were tested separately on the development host. Real CPU
and external NVENC contention tests passed on the research host. These are prior
evidence, not a substitute for checking this new versioned image.

The candidate reuses the exact qualified clean FFmpeg 9 runtime image. Its new
code and notice layers require fresh image checks. Matching dependency sources
and notices are retained separately; privacy, license and source completeness
review must finish before public upload. Generated tests use no library mounts.

For deployment, retain persistent media/output mounts and existing GPU settings.
