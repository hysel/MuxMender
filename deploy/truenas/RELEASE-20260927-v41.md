# MuxMender 20260927-v41

This update fixes several cases where a useful conversion stopped during
preservation checks. Quality and replacement requirements are unchanged.

- Dolby Vision sample and full-file encoding preserve the source chroma
  location. Diagnostics now name the changed field and frame instead of only
  reporting a generic geometry or color mismatch.
- Missing or rounded AAC packet durations require full decoded-audio evidence:
  identical PCM, sample counts and presentation timing. The validator no longer
  crashes on a missing duration field. It does not silently ignore audio errors.
- AV1 can restore constant source content-light metadata without re-encoding
  pictures or rounding mastering-display values. The image includes the pinned
  packet-copy runtime; standalone installations can use the optional hdr-av1 extra.
- Artwork preservation uses the actual extracted attachment paths. DV excerpts
  map source metadata to the selected decoded pictures rather than a guessed
  frame offset.
- Includes the pending shared reliability work: source-identity-aware retries,
  broader long-video sampling, heavy-validator admission, generated-artifact
  tracking, terminal cleanup reconciliation and clearer outcome reporting.

## Tested results and limits

One full HEVC compatibility copy passed validation at 32.76% smaller. A repaired
full Dolby Vision copy passed preservation across 168,464 frames at 26.33%
smaller; all five common-render quality scenes passed the unchanged 90/90 floors.
The lowest scene mean was 92.55 and the lowest fifth-percentile score was 91.10.
The repair preserved compressed picture data and did not re-encode it. These
scores are not percentages of perceptual quality or a native DV perceptual model.

The separate AV1 metadata repair passed all 252 excerpt frames and decoded
picture identity checks. An additional eight-setting AV1 search correctly kept
its source because no candidate met both quality and savings requirements.
This is tested-path evidence, not certification of every source or GPU.

The compatibility copies omitted a damaged audio track with separate, explicit
permission. This is **not** an automatic audio-dropping policy. Research copies
are not automatically approved for replacement and are not counted as reclaimed
library space.

## Deploy and start a new task

Keep the production queue paused during the update. Build and select
`muxmender-app:20260927-v41` in the existing TrueNAS app. Preserve its mounts,
UID/GID, GPU assignment and published port. Verify the dashboard reports v41,
then select the source folder and submit a new conversion task with the desired
copy/replacement and savings settings. Existing jobs retain their saved settings;
inspect pending jobs before resuming rather than adding duplicates.

The current portal is `http://192.168.1.232:8767/`. Deployment does not replace
library files by itself. Existing mounts, history and results are retained.
The release archive is a Docker build context, not a prebuilt or deployed image.
