# MuxMender 20261009-v58

## New files start an empty queue

Adding new processing work to an empty queue starts it automatically, even if
the empty queue was paused. Finished and cancelled history does not count as
waiting work. Keep-original and history-only submissions do not restart work.

A manual pause with waiting or running work remains paused. Worker-error and
restart-recovery pauses still require attention and an explicit resume. Adding
files does not bypass resource admission, GPU sharing or validation.

Queue cancellation and auto-start regressions are included in image smoke
testing. The change does not resume existing deployed queues on its own.

## Read-only performance reporting

The administration tool `tools/analyze_batch_performance.py` reads the existing
queue and job APIs and summarizes one batch without changing it. Reports omit
media names and paths. They show confirmed replacement savings, cleanup status
and accumulated stage timing, including resource waits.

Summed task-stage counters are not batch wall time, CPU utilization or a promised
speed improvement. Active counters and independently cached API data may lag.
Use these measurements to choose benchmarks, not to weaken checks or force
concurrency. A dashboard-recorded review of the current batch found waits were
the dominant cost; broader full-file benchmarks remain pending available GPU
capacity.

Quality, timing, metadata, track preservation, savings and publication checks
remain unchanged. Dynamic worker admission and experimental HDR routes are
unchanged. No performance gain is claimed for this release.
