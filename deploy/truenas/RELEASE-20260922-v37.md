# MuxMender 20260922-v37

## What changed

Servers with large ZFS caches can now start one job when the old fixed memory
threshold would leave an otherwise healthy server idle. The scheduler checks
resident evictable cache, protects ARC's minimum, and waits for 30 seconds of
healthy readings. It requires at least 6 GiB of available host RAM and gives
only bounded credit to reclaimable cache. It does not change ZFS settings.

This cache-assisted route allows one active job, not unrestricted parallel work.
The normal thresholds still apply before adding parallel jobs. Container limits,
memory pressure, CPU, storage and GPU checks remain in place. Unknown cache
telemetry retains the old behavior. This is not a guarantee against peak-memory
failures; first production use should be observed.

All v36 savings options, validation and cleanup behavior are retained. Saved
queue settings and history are unchanged by installing this release.

## Deploy

Build image `muxmender-app:20260922-v37` from the staged context. Keep existing
mounts, GPU assignments, user IDs and settings. Pause the queue and allow active
work to finish before updating. Verify the displayed version after deployment,
then resume the queue. No driver upgrade is required.
