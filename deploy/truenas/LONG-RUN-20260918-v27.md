# v27 — Long-run release candidate

Supersedes v26. Includes all v22–v26 application, safety, measured-validation,
packaging and per-stage telemetry changes. Production GPU decoding stays disabled;
the RTX 5050 experiment showed pixel/timing agreement on generated SDR media and
11.6% less decode/checksum time, not full preservation/error-handling certification.

## Fixes discovered during clean/TrueNAS verification

- Two AMD batch tests selected the newest result by filesystem mtime, which can
  tie on Linux. Tests now observe the exact report path written by the run.
  Repeat-skip behavior itself was correct; no production guard was weakened.
- A preflight unit test did not mock the hardware capability probe. It depended
  on installed GPU tools, causing Linux failure and unintended real GPU work on
  Windows. The unit test now isolates the runtime probe explicitly.
- All required runtime modules are included in the Python wheel. Development
  test dependencies/benchmark tools are explicitly tracked and packaged; generated
  media, binaries, local keys and runtime reports are excluded.

## Operational policy

- Keep quality floors and full-file validation enabled. Source/output frame
  scans, independent full video/audio decoding, copied track evidence, checksums
  and verified replacement checks remain mandatory.
- Existing shared-host governor controls parallelism. Decoder telemetry is now
  considered alongside compute/encoder load; no concurrency limit was raised.
- Jobs publish stage wall-time totals to identify real bottlenecks. The measured
  local full-validation improvement was 27.6%, not an entire-library guarantee.
- Interrupted-stage reuse and combined decode/frame validation remain deferred.
- This release does not resume the queue or authorize additional replacements.
  Existing UI mode/confirmation, history and replacement checks still apply.

Set the existing app image to `muxmender-app:20260918-v27`. Keep mounts, GPU
assignment, ports and environment unchanged. Check the dashboard reconnects, then
resume the queue when desired. Staging a context does not build/deploy the image.
Archive/build folders for earlier versions are left intact; no media is removed.
