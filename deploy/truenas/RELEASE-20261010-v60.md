# v60 — FFmpeg 9 and clearer source errors

FFmpeg 9.0.2 is now the default encoding, probing and quality-metric runtime.
Its sources and dependencies are checksum-pinned. NVENC headers remain at API
13.0, compatible with the tested NVIDIA driver; a driver upgrade is not required
by this build. FFmpeg 8 remains at its original absolute path for diagnosis.

The existing qualified GPU validation reader is retained with its matching
source and evidence bundle. It is a separate helper, not a new FFmpeg 9 reader
certification. The image smoke test must accept that reader in the new runtime
environment before deployment is recommended.

This includes the shared chapter-mapping fixes, diagnostic frame-field details,
narrow DTS terminal-duration restoration and corrected video-reader error
attribution during audio preflight. All existing quality, packet, timing,
metadata and verified-publication checks remain required.

Generated paired qualification passed all 82 modules on both runtimes without
skips. One full source passed on both runtimes with 33.53% savings; two further
historical track-count cases passed the baseline full workflow with 44.08% and
27.11% savings. This is not evidence of faster or smaller FFmpeg 9 encoding.
Genuine AVC and AC3 corruption remains rejected; no repair exception is added.

The package is staged for isolated build and smoke tests. It does not change the
installed app, queue or library. Keep the v59 image available for rollback.
Do not deploy until the staged build reports `status=passed`.

The first staging attempt stopped before Docker because the version guard
retained a Windows carriage return. The revised guard accepts that checkout;
shell files are normalized and revised contexts/status are archive-bound.
