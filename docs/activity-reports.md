# Activity reports

Open **Reports** in the top navigation to see what happened to your videos.
Start with four groups: **Converted**, **Original kept**, **Needs attention**,
and **In progress**. Click a group to filter the list; click it again to show all.
Errors and unsupported inputs appear under Needs attention, not among normal
size or quality decisions.

The default shows the latest outcome per video. Open **History and export** and choose **Every attempt** to
include earlier failures and retries. Archived results remain available here;
clearing the Results view does not erase the report history. Search by file or
folder path. Each card shows a plain-language reason, sizes, and a date in your
browser's local time zone. Open **Details** for the full path and technical reason.

**Download matching report (CSV)** exports all matching loaded records, even
when only the first 25 cards are displayed. Exported dates use UTC. The export includes request ID,
app version, recorded input/output sizes and replacement savings when available.
Missing historical measurements remain blank, not zero or a presumed success.

The Converted group includes replacements and validated copies; each card says
which happened and whether the original remains.
Only recorded replacements count as library reduction. A failed size or quality
check is an unchanged result, not a processing error; an actual evaluation error
stays in Errors even if the original was retained. Cancelling is separate too.

Reports are read-only and reuse the same history/outcome classification as the
dashboard. A disconnected display is marked as potentially stale. Reports contain
private media paths, so review them before sharing. These are production-history
reports; isolated development experiments remain on the development dashboard.
