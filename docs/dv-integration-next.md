# Dolby Vision: next qualification steps

The production skip rule remains enabled. Existing research is scoped to
Profile 8.1 with an HDR10-compatible base layer, not every Dolby Vision profile.

## Evidence already recorded

- Combined Dolby Vision/HDR10+: a full copy passed 81,246-frame preservation,
  including picture geometry, timing, static HDR, HDR10+, RPU semantics and
  copied tracks. Recorded reduction was 86.8553%. Three-scene quality passed.
- Ordinary Dolby Vision: full-copy preservation passed, but the tested broader
  quality/size settings did not qualify. The recorded full-copy reduction of
  10.208% would also miss the current default 25% savings target.

These are historical reports, not fresh verification of retained files or
proof that the automatic app route is integrated.

## Work remaining

The local shared adapter is now implemented behind `--experimental-dv81` in
both the automatic engine and standalone workflow. It reuses the DV sample and
full preservation services, uses the ordinary candidate selector, verifies
matching sample identities and configured quality/savings floors, and records
standard hashes/status. A source/stop/storage guard is propagated into the
preservation stages. The publisher explicitly rejects these qualification
copies; the app does not expose or enable this option yet.

Local tests use generated bytes and mocked encoders to exercise orchestration;
they are not real-file Dolby Vision qualification. Existing real-file research
is retained as evidence rather than repeated from scratch. The remaining live
check is for the new adapter and report handoff. Production packaging also
has been updated locally to require the same checksum-pinned dovi_tool archive
used by research. The running v37 image does not include that packaging change.

1. Restart the isolated research container, then inspect its retained reports
   and current source/output identities. Coordinate with production so GPU and
   memory contention do not undermine either job.
2. Reassess research at the selected savings floor. The shared three-scene
   runner now accepts `--minimum-savings-percent`, defaulting to 25. Sample
   payload savings remain estimates, not full-container savings.
3. Qualify the new adapter and its existing shared quality selection, full-file
   verification, status reporting, cleanup and publication boundary. No separate
   app policy or independent encoding implementation.
4. Exercise separate-copy end-to-end tests for ordinary and combined metadata,
   including negative tests for reordered/lost RPU, HDR10+ loss, timing changes,
   insufficient savings, dependency failure and interrupted finalization.
5. Only remove the skip for routes that pass those checks. Profile 5 and other
   unqualified configurations remain separately reported, not silently converted
   to HDR10 or SDR. No source replacement is part of research qualification.
